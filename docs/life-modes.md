# 生活方向

宿主人设始终优先。生活方向是活动素材，不是替换角色卡：不写入宿主的系统提示词，不自动修改身份、年龄、关系、称呼和说话风格。与宿主人设不兼容的活动应由宿主 Agent 跳过或改编。

默认 **沿用原有人设**：不添加方向提示，保留已有日程模板。另有研究日常、上班日常、大学生活、小学生活、居家陪伴、动物观察、哲学漫游和自定义生活方向。居家陪伴不建立恋爱关系，小学生活不改写年龄。用户可以填写最多400字的生活素材，自定义模式必须填写。

## 使用

面板 → 生活方向 → 选择并保存。今天已有日程时，从明天的新日程生效；尚未建立今天日程时，从今天首次创建日程生效。已存在日程不会被切换操作重建，已确认经历、持续事项与约定保留。恢复默认也遵循同一规则，历史事实不会因此消失。

选择按原有人设标识隔离，保存在已有 life.json 的 lifeModes 字段。不同 binding 的独立数据文件仍然隔离；同角色共享数据的宿主会共享生活方向。配置可用 life.mode={"id":"researcher","notes":"偏爱自然科学"} 设置初始方向；管理面板选择优先。可用 id：inherit、researcher、worker、university、primary、home、zoologist、philosopher、custom。

## 工作方式与成本

新日期建立模板时，按生活方向替换 morning / afternoon / evening 的活动素材，保留宿主配置的起止时间、时段标识及其他活动。非标准时段标识继续保留。独立插件无需接入新的模型 API；宿主原有 Agent 收到当日已生效方向后，可以结合原有人设安排具体活动。方向说明仅注入当天有效的一个选择，不附带全部预设。

本地 QQ 适配还会把方向传入已有的每日规划 Agent，沿用每天一次的规划流程。切换和预览本身不请求模型，也不主动发消息。模板只提供计划，不预先登记经历。原有约定投影继续优先占用已接受时段。

管理 API：POST /life/api/mode?binding=...，管理员令牌鉴权。请求含 id、notes、expectedVersion（来自 view.lifeMode.version）；返回 effectiveDate。旧版本返回409；会话 token 无权修改。写入失败回滚内存，损坏文件保持只读。

## 验证边界

自动测试覆盖默认继承、跨日切换、重启恢复、角色隔离、并发版本冲突、模板状态、管理接口权限。浏览器使用隔离示例验证选择与保存。真实模型是否始终遵循素材与宿主人设之间的优先级，需要在各宿主中持续观察；本功能不声称能自动理解或证明任意角色卡的语义兼容性。
