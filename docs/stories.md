# 连续生活小故事

开启 `life.stories.enabled: true` 后，角色可以把一件虚拟小事延续几天：开始读书 → 读到一半 → 读完后的感受。复用原模型与普通回复回合，无独立定时模型调用。

同时最多 3 条进行中的生活线，每轮最多 2 项变更。按绑定/会话与角色隔离，跨日期保留；不会因为过去一天或电脑离线就自动增加进展。普通聊天不必总提起故事，更不必每次都新开一本书。

## 提交候选

`life_propose` 新增 `lifeStories` 参数：

```json
{"lifeStories":[{
  "action":"create","date":"2026-01-10",
  "subject":"character","basis":"own_virtual_experience",
  "title":"小王子","category":"reading",
  "progress":"刚开始读","nextStep":"明天接着读",
  "facts":{"book":"小王子"},
  "evidence":"小王子刚开始读，明天接着读"
}]}
```

category 是 reading/hobby/daily。title、progress、nextStep 以及 facts 的值须逐字见于本轮成功送达的 evidence；date 必须是当前日期。计划的下一步不属于已发生事实。假设、明显引用他人的句子不接受。

提交后返回生活线 ID。之后用 action=advance/complete/drop、原 id、expectedRevision=最新版本号推进或结束；固定书名等事实不能静默改写，已结束生活线不直接重开。新进展覆盖当前进度并保留修订与最近 8 次证据。人工可以查看原 JSON，但当前没有可视化纠错界面。

如果显式提交的 progress/nextStep 是转述，而 evidence 确实逐字匹配实际发出的文本，本地会尝试选用该原文中的活动句/未来计划句，再进行校验；不会扫描普通聊天自动建立故事。无法修复的字段仍拒绝。返回 repairedFields 以便宿主观察。

核心层可选 `stories.scope="character"` 将同一实例内的角色生活线设为共享公共状态，仅适合宿主明确授权的公共虚拟生活。HTTP运行时仍按绑定分开存储，不会因这个开关打通多个绑定。跨会话共享需要宿主设计公共角色状态域；不要把私人约定和用户信息放入公共生活线。

普通回复携带未结束索引，具体信息按标题、话题、时间表达选择，最多 2 条、正文预算 1800 字符。没有命中可用 `life_context(query=标题)` 读取。只保留有限进度片段，并非完整小说剧本。真实书籍内容仍须准确，不能把虚构情节归给真实作品。

运行时仍须等待宿主发送成功才保存；失败或结果不明不推进、不自动重发。协议能够防止版本冲突与固定字段覆盖，不能完整识别语义上的进度回退或所有反讽。宿主应引导模型自然承接，实际效果仍需真实聊天观察。
