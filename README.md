# Companion Life · 虚拟生活状态实验

为已有聊天机器人补充随时间变化的日程、稳定的虚拟生活细节、七日摘要和未来约定。复用宿主现有模型，不购买新的模型 API；不替换角色卡、收发消息或模型路由。

新增：[连续生活小故事](docs/stories.md)。让“今天开始读一本书”在后续几天承接进度、保存感受；下一步只是计划，时间经过不自动增加剧情。无需增加独立模型调用。

新增：[聊天改变日程](docs/calendar.md)。同意具体时间的邀请后占用日程，改期释放原时段，取消恢复基础计划；已有经历保留。

新增：[生活方向](docs/life-modes.md)。默认沿用宿主人设，可选择研究、工作、校园、居家等活动方向，自定义生活素材，不覆盖身份、关系与说话风格。

新增：[生活手记面板](docs/panel.md)。启动后打开 `http://127.0.0.1:5421/life`，使用管理令牌查看时间线、持续事项与约定，以及可追溯的记录纠错、撤回、恢复。自适应电脑和手机尺寸。

**0.1.0-alpha.1：独立原型。** 这是虚拟角色记忆，不是现实行为证明。本项目不包含 QQ 客户端、生图、手机控制或账号数据，也不是一套完整的 QQ 机器人。

## 快速体验

安装 Node.js **22.13+**。解压本项目，在目录打开终端：

```sh
npm run demo
npm run check
npm run init -- --defaults
npm run doctor
npm start
```

零 npm 运行依赖，无须先执行 `npm install`。`demo` 使用固定回复模拟模型、模拟发送，走真实本地 HTTP 和持久化流程；不会连接 QQ 或调用模型。它不能代替真实模型验收。

Windows 可双击 `Start.bat`；其他系统可运行 `sh Start.sh`。均为手动启动，不注册开机任务。关闭终端或 Ctrl+C 停止。没有配置时启动器生成本机随机令牌；不会覆盖现有配置。`config.local.json` 和 `data/` 必须保密。

## 能接什么

| 接入方式 | 本版状态 | 需要宿主做的事 |
| --- | --- | --- |
| 自建 Node.js 机器人 / qq-bridge 类项目 | HTTP SDK 已做模拟端到端测试 | 在模型前注入上下文、注册候选工具、发送成功后提交 |
| 支持 MCP 的 Agent | stdio 握手与工具测试通过 | 仍需宿主维护回合和提交成功发送回执；只安装 MCP 不会自动记忆 |
| OneBot v11 网关 | 发送适配器通过协议模拟测试 | 提供现有网关地址和固定收件目标；模型入口由宿主提供 |
| AstrBot、NoneBot 等框架 | 可通过通用接口开发适配；未完成真实宿主验收 | 参照接入契约编写钩子，不声称已安装即用 |
| QQ 官方机器人 | 未提供专用适配器 | 使用官方收发层实现相同的宿主契约 |

OneBot 是收发协议，MCP 是工具协议，都不能代替模型前后钩子。首版没有将不同框架伪装成同一种“一键安装插件”。[接入说明](docs/integration.md)包含可直接复用的 Node 示例和迁移检查项。

## 工作流程

```text
宿主白名单 / 群聊 @ 检查
 → 创建回合，取得当前日程和相关细节
 → 现有模型生成回复，可调用 life_propose 暂存候选事实
 → 宿主沿用原发送工具
 → 发送成功：用实际发出的文本提交 → 校验 → JSON 落盘
 → 发送失败或结果不明：不确认事实，不自动重发
```

`life_propose` 不发送消息，也不直接保存事实。交付令牌只交给宿主，不交给模型。**模型完成推理不等于发送成功。** 保存失败也不能再次发送已送达的回复。

## 配置与记忆

每个 `bindings[]` 代表一个私聊或群聊，使用独立随机令牌和独立数据目录。群聊必须关闭私聊约定和主动分享。默认 `demo` 仅是本地示例绑定，不会向任何 QQ 发送消息；接入时由宿主把实际会话映射到绑定，禁止让模型选择接收者。

`life.enabled=false` 关闭上下文与记录。保留已有数据，重新启用可继续使用。日程可用 `life.schedule` 或 `life.roleSchedules` 配置，按时间排序、不重叠、不跨午夜；角色标识变化会隔离新的日程记录，不会自动清理宿主聊天上下文。默认采用通用阅读日程，接入者应按自己的人设修改模板。当天首次访问时生成当天计划；不会每天额外请求模型来排日程。

完整粗略日程一直提供，具体细节按话题和时间段选取；七日摘要由本地代码在访问时维护，不调用模型、不删除原始数据。未来约定要求当前私聊请求与实际送达的接受文本；到期不自动算完成。见[数据契约](docs/data.md)。

主动分享默认关闭。启用后本地每分钟检查场景切换，仅产生分享机会；仍需宿主保活、领取、调用自己的模型并发送。静默时间、每日次数、冷却、最近互动与持久化去重都生效。它不是自带模型的独立主动聊天机器人。见[主动分享](docs/proactive.md)。

## 成本、安全与局限

- 无新增付费 API，无遥测。注入文本、工具描述和主动分享仍会占用**宿主模型**的 token / 订阅额度；没有“零 token 记忆”。
- 默认仅监听本机回环；不支持直接暴露公网。每个绑定独立鉴权，管理令牌不能替代会话令牌。
- 保存的是选定的虚拟事实、来源证据片段与约定，不保存完整聊天流水。JSON 是明文，应保护备份和系统账户权限。
- 校验能拒绝无证据、明显假设、错误日期和已有字段冲突，但不能准确识别所有反讽、引用和语义矛盾。不同键名表达同一事实也可能漏检。
- 冲突在发送后的记录阶段拦截：旧事实保留并写修订记录，**不保证模型每次都不会说错**。真实模型是否稳定调用工具必须在目标宿主中验收。
- JSON 适合小规模单实例，不适合多进程共享写入。运行时有目录锁；原始记录会增长，需自行备份和管理保留周期。
- 本版本只测试协议与模拟发送；没有把任何框架的真实 QQ 会话宣布为已认证兼容。[验收方法](docs/testing.md)。

## 发布与开发

```sh
npm run privacy
npm run check
npm run release
```

生成本地 `.tgz`、SHA-256 和文件清单到 `artifacts/`，不上传。正向文件清单排除配置、记忆、日志；扫描不能代替人工审阅。CI 在 Windows / Ubuntu 和 Node 22 / 24 运行相同检查。
